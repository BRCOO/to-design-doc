# to-design-doc

把对话中的需求写成一份**精简中文技术方案**的 Agent Skill。手动触发 `/to-design-doc`，从零写，固定 6 节骨架，每节只回答一个问题。

## 特性

- 固定 6 节骨架：需求 / 调用位置 / 结果使用方式 / 处理规则 / 代码改动 / 验收标准；某节没有实质内容就删掉，不留空节凑结构
- 无实现代码与结构体/字段定义；允许少量简洁伪代码（仅当比文字更清楚）；字段级细节压成一句话
- 同一事实或规则只写一次
- 表格只用于多列对照信息（场景×期望、选项×利弊、字段×规则）；单句清单用分点
- 内置金标准样例与输出前自查清单（5 条，全部通过才交付）

## 安装

```bash
# 方式一：clone 到个人 skills 目录（推荐）
git clone https://github.com/BRCOO/to-design-doc.git ~/.agents/skills/to-design-doc

# 方式二：手动复制
# 将 SKILL.md 与 agents/openai.yaml 放到 ~/.agents/skills/to-design-doc/ 下
```

## 使用

新会话输入 `/to-design-doc`，在对话里把需求讲清楚（做什么、给谁用、输出什么、边界条件）。核心决策缺失时最多问一轮。只从零写：已有草稿只作为需求与决策的来源，产出按本骨架重写，不沿用草稿的结构和句子。

## 骨架

| 节 | 回答的问题 |
|---|---|
| 需求 | 要做什么？给谁用？输出什么结果？ |
| 调用位置 | 新逻辑插在现有调用链的哪一步？ |
| 结果使用方式 | 各使用方分别读哪些结果、怎么用？ |
| 处理规则 | 判定规则和边界条件是什么？ |
| 代码改动 | 改哪些文件/函数、各做什么？ |
| 验收标准 | 什么场景下应观察到什么结果？ |
